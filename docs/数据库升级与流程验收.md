## 升级与部署

统一入口目前支持 PostgreSQL。固定版本包括核心结构基线、成长行动计划、制度与校园活动，执行记录和内容校验值保存在 `schema_migrations`。空库可初始化全部结构，不创建默认账号或演示数据；已有兼容核心库可登记基线，并补齐缺少的新功能表。

在 `server` 目录运行：

```sh
npm run db:status
npm run db:check
```

两条命令都只读，不创建版本表。`status` 展示目标库、待执行版本与结构问题；`check` 在版本未就绪时以失败状态退出，供部署流程拦截。

维护者获得升级授权，确认目标库并停止业务写入后，再执行：

```sh
npm run db:upgrade -- --confirm-database <实际库名> --maintenance-confirmed
```

升级前自动以 `pg_dump` 完整备份已有库，存入配置的本地备份目录，核验数据库名称、归档可读性和 SHA-256。备份失败或校验不符时不继续。Windows 自动寻找已安装 PostgreSQL 客户端，也可设置 `PG_DUMP_PATH`、`PG_RESTORE_PATH`；其他系统从 PATH 查找。客户端版本应与数据库匹配。

升级使用事务及 PostgreSQL advisory lock，跨进程不能同时执行；中途失败时结构与版本记录一起回滚。未知版本、校验值不符、前置版本缺失、字段漂移和关键唯一索引缺失都会拒绝。不会通过 ORM 自动修改或强制重建旧表。更早的历史库若缺少核心表或字段，会列出问题，需先按旧版本修复后再接管。

程序启动前只读检查必要结构，缺表时拒绝提供不完整服务。结构完整但未登记版本的旧库保留兼容启动并给出维护提示；Windows 部署启动脚本要求统一版本就绪。

当前本机业务库只读检查结果：23 张业务表结构齐全、无结构问题，三个版本均可直接接管；本轮尚未向日常库写入版本记录，原有服务继续运行。

## 真实数据库流程验收

在 `server` 目录运行：

```sh
npm run test:workflow-db
```

脚本只在本次随机新建的两个测试库中操作，实际使用项目路由、JWT 登录、权限中间件、计分服务及 PostgreSQL。账号、学校、班级和经历均为合成数据，不调用真实 AI、不读取真实附件；结束时仅删除本次创建的测试库。

覆盖范围：

1. 空库初始化、既有库接管、后续字段升级、只读检查、幂等、目标确认、结构与版本校验、并发锁、失败回滚、备份失败保护和启动缺表检查。
2. 登录、关闭学期拒绝正式申报、草稿暂存、开启后提交、重复申报拒绝、班级初审、并发审核、辅导员改分及终审驳回、汇总分数一致。
3. 学生与教师的跨人、跨班、跨校拒绝，报表生成、上报、退回、重报和通过。
4. 制度草稿隔离、发布引用、修订保留旧文，活动筛选、加入计划、重复加入拒绝，成长记录提交、教师核验、历史与版本冲突、活动撤回，以及成长核验不自动加分。
5. 完整备份实际恢复到另一空测试库，对比 24 张表（含版本表）的逐表数据指纹，确认内容一致。

本轮 32 组隔离数据库验收、72 项常规检查及前端构建均通过。无个人信息的证据见 [验收报告](../output/verification/database-workflow-20261021.json)。这些结果不代替真实师生试用和 AI 准确率测量，也不代表本脚本穷尽全部接口；上传识别、注册审批、申诉、导入等仍有各自专项检查。

## 后续维护

历史 SQL 与基线结构契约保持冻结。增加新版本应新增 SQL 并在 `schemaMigrations.js` 注册递增编号；已有表增补字段可声明 `kind: 'change'` 以及该版本完成后的 `tables`、`columns`。先验证成功及失败路径，再安排维护窗口。

数据库备份、真实配置、日志、用户附件和工具元数据不纳入源码备份或部署包。恢复演练验证的是合成测试库，正式恢复仍需维护窗口和明确授权。
