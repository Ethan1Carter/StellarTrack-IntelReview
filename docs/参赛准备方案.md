## 1. 参赛定位

- 建议赛道：AI＋管理（校园智慧管理）。如报名时已选择其他赛道，先核对是否可调整。
- 建议作品名称：星轨智评——AI 五育成长评价智能体。以实际报名名称为准，材料命名保持一致。
- 对应官方参考方向：附件 4“AI＋管理”方向 1 中的评奖评优、综测核算（原 PDF 第 20 页）。
- 核心用户：学生、班级管理员、辅导员；学校及学院管理人员负责规则配置和汇总。
- 核心问题：材料重复录入、证明材料与评分规则难以核对、审核成本较高、学生难以将评价结果转化为行动。
- 演示主线：上传证明 → 提取成果事实 → 匹配评价模块并说明依据 → 学生确认申报 → 教师复核 → 五育画像及可跟踪的成长建议。

主张以可检查的材料事实、明确的计分规则和人工复核构成可信评价流程。不要把模型建议直接当作最终得分或材料真实性鉴定。

## 3. 评分对照与取舍

初赛：创新性 30 分、实用性 30 分、技术实现 20 分、展示效果 20 分（第 10–11 页）。

决赛：应用价值与效果 45 分、创新性 25 分、技术实现 15 分、现场表现 15 分（第 16–17 页）。

| 评分项 | 项目现有基础 | 接下来需要的证据或改进 |
| --- | --- | --- |
| 创新性 | AI 材料审核入口、五育评价业务 | 展示材料事实与规则依据的关联，以及评价后可执行的成长任务；说明区别于手工综测的实际变化 |
| 实用性 | 申报、审核、得分、画像及组织权限等业务基础 | 完成真实数据库下的全流程验证；用小规模试用记录证明减少了哪些步骤和耗时 |
| 技术实现 | 自建前后端、模型接口、规则计算、权限控制 | 明确模型和确定性规则的分工；展示异常降级、复核记录、可复现测试 |
| 展示效果 | 已有业务页面 | 用同一名演示学生讲完整案例；文档、视频和现场数据保持一致 |
| 落地成熟度 | 已补充部署和备份相关保护 | 单独演示环境、至少 3 个可用测试账号、演示材料及恢复方案；不暴露真实学生资料 |

管理后台菜单数量不是核心创新证据。优先投入能直接提高上述评分项的工作。

## 4. 当前能力边界

以下按当前源码及上一轮验证记录整理，不等同于已上线或实际试用：

- 已有图片通过兼容模型接口进行材料事实提取、分类及评分建议的实现；外部模型是否可正常工作仍须在演示环境实测。
- 未配置模型或调用失败时，会退回本地规则。此结果应展示为规则辅助结果，不能表述为大模型识别成功。
- PDF 现已完整读取限制页数内的页面图像，由视觉模型提取正文事实并附页码；组件不可用或超页数时不猜测归属。
- 评分依据现可引用管理员配置的模块规则原文，并保存版本摘要。此能力不是外部官方制度知识库，也不等同于 RAG；制度来源与适用学年仍需实际维护者确认。
- 分析看板和现有成长计划主要由规则/模板生成，不能统一描述为大模型自主诊断。
- 成长计划已接通学生记录、证明附件、教师核验与历史过程，并在真实 PostgreSQL 隔离 schema 中验证持久化与并发控制。
- 最新检查结果见更新说明；自动化和合成样例验证不是模型准确率评测，也不替代真实师生试用。
- 尚无本轮可核实的真实试用人数、准确率或效率提升数据；申报材料不能写成已经取得的成效。

## 5. 参赛版本改进顺序

### P0：先把核心 AI 流程做实

1. 补齐 PDF 处理：文本型 PDF 提取正文；扫描件采用页面识别或明确转人工处理；限制页数、体积及调用成本。
2. 将提取事实与来源对应：字段显示来自附件哪一页/哪段事实；无法确认时留空并提示复核。模型给出的 confidence 只作提示，不解释为经校准的准确概率。
3. 完善评分依据：使用已确认的校/院评价规则，记录适用范围、学年和版本；明确命中条款、分值上限、排除条件。没有规则时不编造分数依据。
4. 人工确认和留痕：区分 AI 建议、学生确认内容和教师最终结论；保存修改原因与时间，便于现场解释。
5. 明示运行来源：真实模型、规则降级、待人工核验分别展示。超时、空白页、模糊材料等异常能完成可解释的处理。

验收：一份可正常识别的图片、一份 PDF、一份信息不足的材料、一次模型不可用场景，都能走到明确的人工处理或申报结果。

### P1：让“五育成长”有可展示的结果

1. 接入现有成长计划接口，建议应关联学生已有画像及材料。
2. 每项任务具备目标、行动步骤、截止时间、完成证据及状态。
3. 学生能记录完成情况，教师能查看并反馈，刷新后状态保留。
4. 没有真实活动库时，只给出活动类型建议，不虚构校园活动名称、时间或报名链接。

验收：从画像进入一项成长任务，提交完成证据，教师反馈后能查看历史。此功能完成前只描述为规划方向。

### P1：验证比赛演示可用性

- 在独立演示数据库中准备学生、班级管理员、辅导员三类测试账号；“至少 3 个账号”是赛事要求，选择这三类是本项目建议。
- 验证上传、模型调用、申报、审核、计分、分析、退出与重新登录。
- 演示数据明确标注为示例；使用真实案例则先脱敏并确认使用许可。
- 复核演示账号可访问范围和附件权限，避免评委测试时看到其他真实用户资料。
- 准备可恢复的演示数据及录制好的真实演示视频。故障时说明状态，不将录屏冒充实时调用。

### P2：用实测支撑效果描述

建议使用 20–30 份经许可且脱敏的材料建立小样本集，这个数量是准备建议，不是赛事规定。

- 覆盖图片、文本 PDF、扫描 PDF、缺少日期、等级不明确和无关材料；记录样本范围与限制。
- 人工标注标题、日期、证书编号、等级、匹配模块，记录模型原始结果、修改情况及耗时。
- 分字段计算正确率，单列空值和需人工复核比例；不要将固定模型置信度当作实测准确率。
- 对同一批样本比较纯人工与 AI 辅助流程，报告样本数、中位耗时和错误情况；尽量平衡处理顺序以减少熟悉效应。
- 记录模型版本、调用成本和测试日期。结果只覆盖该小样本，不外推为全校效果。

## 7. 申报与演示材料清单

应用文档按附件 2-1 填写：负责人及成员信息、作品名称、组别、赛道，以及以下七部分。

| 部分 | 字数上限 |
| --- | --- |
| 智能体简介 | 500 字 |
| 需求分析 | 500 字 |
| 设计理念与思路 | 1000 字 |
| 技术实现方法 | 1000 字 |
| 使用说明 | 500 字 |
| 应用/预期效果 | 1000 字 |
| 使用场景分析 | 500 字 |

没有真实试用数据时，在“预期效果”中如实说明预期和验证计划。外部模型/API、第三方库、制度文件、图片素材及数据分别列出具体来源和用途。

建议视频采用约 4 分钟的一条案例主线：痛点 20 秒 → 上传识别与来源核对 70 秒 → 人工复核和计分 60 秒 → 画像与成长任务 60 秒 → 实测结果及适用边界 30 秒。各段仅演示已经完成的能力。

决赛准备：10 分钟内 PPT＋演示；访问地址；至少 3 个有效测试账号及密码。账号密码不提交到公开源码仓库。

诚信承诺书使用官方附件，所有作者亲自核对并签字；核对既往获奖及重复参赛情况。不得代签，不将未实现功能或预期成效写成已经完成。
