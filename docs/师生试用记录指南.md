# 师生试用记录指南

本文件提供验收方法，不表示已经完成真实师生试用。请在获准的测试环境中，由教师与学生实际操作后记录；不要在模板内保存姓名、学号、材料正文、个人联系方式或密码。

复制同目录的 `试用记录模板.csv`，每个案例填一行：

- `case_id`：随机匿名编号，只允许字母、数字、下划线和连字符，勿用学号。
- `task_kind`：制度问答填 `policy`，材料审核填 `material_review`，活动筛选填 `activity`，成长任务填 `growth`。
- `expected_match`：人工核对后是否应匹配该条款、材料或活动，填 `yes` 或 `no`。
- `actual_match`：系统实际是否匹配，填 `yes` 或 `no`；未完成判断时留空。
- `baseline_seconds`、`assisted_seconds`：同一案例人工完成与使用辅助功能完成的秒数。缺测留空，不填 0。
- `source_verified`：人工核对引用、版本与适用范围后填 `yes` 或 `no`，未核对留空。

覆盖正常案例和反例：其他院系/年级、过期制度、撤回活动、材料缺失、多义追问、重复成果和并发修改。至少分别记录成功与失败案例，不能只挑成功页面。

使用 `node scripts/analyze-pilot.mjs <记录文件路径>` 可输出匿名汇总，包括样本数、正确率、误匹配、漏匹配、引用核对比例与成对耗时中位数。每个指标都有自己的有效样本分母；缺测不当作 0，负节省表示比人工更慢。分析脚本不联网、不读取数据库，也不自动收集用户行为。

正式上线前，由维护者先确认数据库备份、升级新增资源表，再录入已核对的真实制度和校园活动。Sites 示例不能用于评估真实 AI 识别准确率，也不能当作学生资格或评分决定。
