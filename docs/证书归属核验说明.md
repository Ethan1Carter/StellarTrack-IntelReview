# 证书归属核验修复说明

更新：2026-10-19。

后续进展：PDF 逐页识别、规则引用、人工修改说明和成长计划已接通，最新验证见[参赛版本更新说明](./参赛版本更新说明.md)。下方“首轮验证记录”保留首次修复时的验证范围。

## 修复原因

原流程只判断文件是否由当前账号上传，没有提取证书获奖人与账号身份比较。上传他人的证书也会返回成果分析和评分建议。

## 当前处理

1. 从鉴权后的服务端用户资料取得真实姓名和学号，不使用客户端指定的身份。
2. 模型独立提取附件中的获奖人、明确标注的学号及原文依据。不给模型提供预期账号姓名和学号，避免迎合预期答案。文件名、补充标题和说明不能作为归属依据。
3. 后端对姓名及明确学号做比较，只允许规范化空格、全角字符和字母大小写后的完整匹配，不做姓名子串或模糊匹配。
4. 证书归属、一般成果分析和最终人工审批分别展示。

| 结果 | 处理 |
| --- | --- |
| 身份信息一致 | 可以带入申报；仍需教师核验原件。仅姓名一致时明确提示同名风险 |
| 姓名未包含本人、相同姓名但明确学号不符 | 显示归属不符，暂停分值建议，禁止从该 AI 结果单份或批量申报 |
| 模糊、缺少获奖人、没有原文依据、账号缺少必要身份、学号疑似漏读 | 显示无法核验，暂停分值建议，不进入批量申报，可转人工填写与核验 |
| 团队证书 | 必须明确列出本人；只有团队名称而没有个人成员，转人工核验 |
| 模型故障或未配置 | 规则降级不能冒充归属核验成功 |
| PDF | 已按页转换为图像交给模型读取，核对获奖人时必须提供有效页码；默认最多 5 页，超限或组件不可用时转人工 |

材料页显示账号姓名、提取获奖人和原文依据；申报页、审核中心及详情页保留归属核对提示。

## 核对记录与申报

- 服务端对原始分析结果签名，绑定账号、身份资料和附件 URL。有效期为 7 天，账号身份修改后需要重新分析。
- 新增申报、编辑及重新提交均使用签名中的原始结果。浏览器修改 `ownership.status` 或评分建议不能覆盖服务端记录。
- 附件被整体替换后清除旧的 AI 分析关联，避免新附件沿用旧结论。
- 旧缓存或旧记录缺少签名时，只显示未核验，不能当作已通过归属核对。
- 原有人工申报流程保留；本次没有将所有附件改为强制 AI 审核，也没有提供证书签发机构的在线验真。

识别与比较只能提供身份信息是否一致的辅助证据，不能证明图片未被篡改或账号身份已经实名核验。模型可能错读文字；显示不符时应核对原件，不直接认定学生造假。

## 首轮验证记录

- 全量自动化测试：24 项通过，其中本次新增 9 项，覆盖后端识别比较、真实 HTTP 分析接口、签名校验及前端申报行为。
- 前端生产构建通过。构建初次受沙箱目录读取限制，获得工具放行后成功完成；既有 Sass 等构建提示未在本次处理。
- 使用已配置模型实际识别一张“合成测试样例，不具有效力”的证书：提取获奖人李四，与测试账号张三判定不符，分值建议为 null。该验证不使用真实学生资料，不连接数据库。
- 实际模型试验中也观察到学号字符可能漏读；比较逻辑将同名但学号位数异常的结果转人工核验。单张样例不代表模型识别准确率。
- 未执行真实数据库申报审批全流程，未自动重启正在运行的服务，未进行数据库迁移。

如需复测真实模型，在项目目录显式运行 `node server/scripts/ai-ownership-smoke.js --live`。该命令读取后端已有配置并产生一次模型调用，输出合成样例的核对结果，不打印密钥。

代码更新后，需重启后端、刷新前端，并对旧材料点击“重新分析”，才能取得新的归属核对结果。
